System Documentation: BambrolistanWheels Marketplace
1. System Overview
The BambrolistanWheels Marketplace is a backend application built using C++ to manage vehicle listings and user interactions. The system uses Object-Oriented Programming (OOP) to ensure data security, code reusability, and modular design.

2. Technical Requirements Fulfillment
Abstraction (Interfaces)
The system uses four abstract classes to define mandatory behaviors for different components. These classes contain pure virtual functions and cannot be instantiated:

BaseComponents: Enforces a standard view for all visible items.

RegulatoryAudit: Provides a template for system-wide verification tasks.

Tax: Ensures every vehicle type implements its own tax calculation logic.

Authorization: Standardizes the credential verification process for users.

Inheritance
The code uses a hierarchical structure to share common attributes and behaviors:

User Hierarchy: BaseUser acts as the parent class for Buyer and Admin.

Vehicle Hierarchy: BaseVehicle acts as the parent class for Car and Bike.

Interface Inheritance: Derived classes inherit from multiple abstract interfaces to combine functionalities (e.g., Car is both a BaseComponents and a Tax entity).

Polymorphism
Polymorphism allows the system to process different objects through a single interface:

Function Overriding: Methods like viewDetails() and calculateTaxRate() behave differently depending on whether they are called on a Car, Bike, Buyer, or Admin object.

Dynamic Binding: The marketplace can store various vehicle types in one array and call the correct specialized methods at runtime.

Operator Overloading
Custom logic is applied to standard operators to simplify complex operations:

==: Used to check if two vehicles are identical by comparing their unique Vehicle Identification Numbers (VIN).

< / >: Used to compare the price of vehicles for sorting or filtering.

+: Used to sum the prices of two vehicles, useful for calculating total portfolio or bundle values.

Friend Functions
Friend functions are used to access private and protected data members in specific, controlled scenarios:

administrativePasswordReset: Allows an administrator to reset a user's private password.

applyDiscount: Allows the system to modify a vehicle's private price member directly during sales.

verifyAdminClearance: Grants an external audit function access to an Admin’s private clearance level.

3. Object Relationships
Composition
The BaseVehicle class uses Composition by including an Engine object as a data member. The engine is a part of the vehicle and its lifecycle is tied directly to the vehicle.

Aggregation
The system uses Aggregation in two places:

MarketplaceListing: Contains a pointer to a BaseVehicle. The vehicle exists independently of the listing.

BambrolistanWheelsMarketplace: Stores an array of pointers to MarketplaceListing objects. This allows the marketplace to manage listings without owning the data itself.

4. Static and Constant Members
Static Members: UsersCount and globalListingCount track the total number of users and ads created across the entire application.

Constant Members: The vehicleIdNo (VIN) is a const string, ensuring that once a vehicle is created, its identity cannot be changed.

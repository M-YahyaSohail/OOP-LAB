# Documentation: BambrolistanWheels Marketplace System

## 1. System Overview
The **BambrolistanWheels Marketplace** is a backend application developed in C++ to manage high-end vehicle listings and user interactions. The system is architected using advanced Object-Oriented Programming (OOP) principles to ensure modularity, scalability, and security.

## 2. Technical Requirements Audit

### Abstraction (Requirement 3)
The system implements four abstract classes to establish a strict interface for all derived components. These classes contain pure virtual functions, ensuring that no "incomplete" objects are instantiated:
*   **`BaseComponents`**: Defines the standard viewing contract for all entities.
*   **`RegulatoryAudit`**: Provides a template for system-wide verification and compliance.
*   **`Tax`**: Forces every vehicle to implement its own specific taxation logic.
*   **`Authorization`**: Standardizes the credential verification process for security.

### Inheritance (Requirement 1)
The system utilizes a multi-level hierarchy to maximize code reuse:
*   **User Hierarchy**: `BaseUser` is the parent class for specialized roles: `Buyer` and `Admin`.
*   **Vehicle Hierarchy**: `BaseVehicle` serves as the parent for `Car` and `Bike`.
*   **Interface Inheritance**: Derived classes inherit from multiple abstract interfaces to combine capabilities.

### Polymorphism (Requirement 2)
Dynamic binding is used to handle various object types through base pointers:
*   **Function Overriding**: Methods like `viewDetails()` and `calculateTaxRate()` behave differently depending on the derived class being accessed.
*   **Example**: `displayDetails()` behaves differently for each vehicle type (Car vs. Bike).

### Operator Overloading (Requirement 4)
The system overloads four standard operators to provide meaningful logic for marketplace operations:
*   **`==`**: Compares vehicles based on their unique Vehicle Identification Number (VIN).
*   **`<` / `>`**: Simplifies the process of comparing vehicle prices for filtering.
*   **`+`**: Combines vehicle prices to calculate bundle values or portfolio totals.

### Friend Functions (Requirement 5)
Specific friend functions are implemented to allow secure access to private data for administrative tasks:
*   **`administrativePasswordReset`**: Allows administrators to modify private user passwords.
*   **`applyDiscount`**: Grants access to modify private vehicle price members for marketing.
*   **`verifyAdminClearance`**: Accesses private admin clearance levels for security audits.

## 3. Object Relationships

### Composition (Assignment 01 Integration)
The `BaseVehicle` class uses **Composition** to manage its `Engine`. The engine is an internal component of the vehicle and its lifecycle is managed by the vehicle object.

### Aggregation (Assignment 01 Integration)
The system utilizes **Aggregation** to manage data without ownership:
*   **`MarketplaceListing`**: Contains a pointer to a `BaseVehicle`. The vehicle remains independent of the listing.
*   **`BambrolistanWheelsMarketplace`**: Manages an array of pointers to listings, allowing the marketplace to facilitate trades without owning the underlying data.

## 4. Static and Constant Members
*   **Static Members**: `UsersCount` and `globalListingCount` provide a global view of system activity.
*   **Constant Members**: The `vehicleIdNo` is defined as a `const string` to ensure the identity of a vehicle cannot be altered after creation.
